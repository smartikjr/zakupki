# Поиск подрядчиков через вакансии — ГК «БЛОК»

Второе, отдельное от корневого сборщика лидов, приложение. Реализует
методику поиска заказчиков не через госзакупки, а через рынок труда и
поиск в интернете (см. скриншот методички, п.7–9):

- **п.7 «Поиск заказчиков... на сайтах, где размещены вакансии»** —
  автоматизировано полностью: ищем на hh.ru вакансии вроде «Начальник
  строительного участка» — компании, которые их публикуют, обычно
  ведут стройку прямо сейчас.
- **п.8 «Поиск заказчиков при выезде на объект»** — это полевой метод
  (ехать и физически спрашивать на площадке), автоматизации не
  подлежит. В приложении не реализован.
- **п.9 «Формулировки в поисковой строке»** — готовим кликабельные
  ссылки на Яндекс/Google по типу «дорожные строительные компании
  СПб», но **сами результаты поиска не парсим** (см. «Почему поиск не
  автоматизирован» ниже).

Результат — файл `companies.xlsx` с двумя листами: «Компании (HH.ru)»
и «Ссылки для поиска».

## Установка
```bash
pip install -r requirements.txt
```

## Запуск локально
```bash
python main.py
```
Токен DaData — тот же принцип, что в корневом сборщике: переменная
окружения `DADATA_TOKEN` или поле `dadata_token` в `config.yaml`. Можно
использовать один и тот же токен DaData для обоих приложений — они не
делят лимит между собой автоматически, просто оба тратят из одной и
той же квоты 10 000 запросов/день.

## Как это работает
1. Для каждой должности из `config.yaml → job_titles` ищем вакансии на
   hh.ru (открытое API, авторизация не нужна) в каждом регионе из
   `regions`.
2. Группируем найденные вакансии по работодателю — одна компания часто
   даёт несколько вакансий/регионов, в выгрузке это одна строка со
   списком должностей и количеством вакансий.
3. Отсеиваем казённые/бюджетные организации по названию (тот же список
   ключевых слов, что и в корневом сборщике — см. `exclude_customer_keywords`).
4. Обогащаем через DaData (ИНН, регион, руководитель, ОКВЭД).
5. Строим лист готовых поисковых ссылок (п.9).
6. Сохраняем в `companies.xlsx`.

## Почему поиск в Яндексе/Google не автоматизирован
- Яндекс агрессивно блокирует автоматические запросы к своему поиску
  (капча почти сразу) — надёжно спарсить результаты не получится, а
  если и получится сегодня, сломается при следующем обновлении защиты.
- У Google есть официальный Custom Search API, но он платный/с жёстким
  бесплатным лимитом (100 запросов/день) — для регулярного прогона по
  многим регионам и категориям быстро упрётся в лимит.
- Оба варианта прямо нарушают условия использования при автоматических
  запросах без официального API.

Поэтому вместо парсинга — просто готовые ссылки: экономят время на
наборе запроса, дальше просматриваешь результаты сам, как и раньше.

Если всё же нужен настоящий автоматический поиск компаний по каталогу
(не через веб-поиск) — присмотрись к API 2ГИС (2gis.ru) — у них есть
каталог организаций по рубрикам/регионам, рассчитанный именно на
такое использование (нужна регистрация, есть бесплатный лимит). Это
можно добавить отдельным источником, если понадобится — сейчас не
реализовано.

## Если hh.ru не находит регион
В логе будет строка `[!] Не нашёл на hh.ru регион(ы): ...`. Значит
название в `config.yaml → regions` не совпадает с тем, как регион
называется на hh.ru. Поправь формулировку (например, `Краснодарский
край` вместо `Краснодар`) — можно свериться на самом hh.ru: открой
поиск вакансий, выбери регион в фильтре и посмотри точное название.

## Настройка под себя — `config.yaml`
- `job_titles` — какие должности искать. Уже заполнено под методичку
  («Начальник строительного участка», «Прораб» и т.д.) — дополняй под
  свои задачи.
- `regions` — регионы поиска.
- `exclude_customer_keywords` — слова в названии компании, при которых
  запись отбрасывается.
- `search_categories` — категории для листа готовых поисковых ссылок.
- `pages_per_query` — глубина по каждому запросу (50 вакансий на страницу).
- `hh_proxy` — на случай, если hh.ru окажется недоступен с серверов
  GitHub Actions (пока не требовался).

## GitHub Actions
Воркфлоу `.github/workflows/vacancy-leadgen.yml` (в корне репозитория)
запускает это приложение и кладёт `companies.xlsx` в репозиторий —
аналогично корневому `leadgen.yml`. Сначала запусти вручную (`Actions
→ Поиск подрядчиков (HH.ru) → Run workflow`) и проверь результат,
прежде чем полагаться на расписание.
