# Четвёртое приложение — НОСТРОЙ (реестр СРО строителей)

Четвёртое, отдельное от остальных трёх приложений (корневой сборщик,
`vacancy-leadgen`, `erz-rts-leadgen`), приложение. Собирает лиды из
Единого реестра членов СРО строителей (nostroy.ru) — выгружает
**отдельный** файл `nostroy.xlsx`.

Зачем этот источник: официальный реестр всех строительных компаний с
допуском СРО (обязателен по закону для большинства строительных работ)
по регионам. В отличие от тендерных площадок (только те, кто участвует
в конкретной закупке прямо сейчас) и ЕРЗ.РФ (только жилые застройщики)
— здесь просто ВСЕ компании с допуском к строительству в регионе,
включая тех, кто пока нигде не засветился в тендерах, но реально ведёт
стройки. Более "холодная" база, зато самая широкая.

## Статус: селекторы ещё не откалиброваны

Как и было изначально с zakupki.gov.ru/b2b-center.ru/erzrf.ru — домен
nostroy.ru недоступен из песочницы, где писался код. `nostroy.py` —
рабочий каркас с угаданным URL реестра (скорее всего на отдельном
поддомене `reestr.nostroy.ru`), ещё не проверенный на реальном HTML.

Калибровка — по той же схеме, что для остальных источников:
1. Прогнать `.github/workflows/nostroy-leadgen.yml` — он снимет HTML
   главной nostroy.ru, главной reestr.nostroy.ru и попытки поиска в
   `debug_nostroy_*.html` и закоммитит их в репозиторий.
2. Посмотреть меню главной страницы — найти реальный адрес реестра
   (именно так нашли правильный `/zastroyschiki` для ЕРЗ.РФ).
3. Поправить `build_url()`/`parse_cards()` в `nostroy.py`.
4. Повторить при необходимости.

## Установка
```bash
pip install -r requirements.txt
```

## Запуск локально
```bash
python main.py
```
Токен DaData — тот же принцип, что в остальных приложениях: переменная
окружения `DADATA_TOKEN` или поле `dadata_token` в `config.yaml`.

## Накопление между прогонами
Как и в остальных приложениях — уже выгруженные раньше записи (по
ИНН/ОГРН, а если их нет — по названию) не повторяются, добавляются
только новые. Чтобы начать историю заново — удали `nostroy.xlsx` перед
прогоном.

## Настройка — `config.yaml`
- `regions` — регионы для поиска в реестре.
- `exclude_customer_keywords` — слова в названии, при которых запись
  отбрасывается (казённые/бюджетные организации).
- `pages_per_region` — глубина сбора.
- `proxy` — на случай блокировки с серверов GitHub Actions (см.
  `ZAKUPKI_PROXY`/`HH_PROXY`/`ERZ_RTS_PROXY` в других приложениях —
  тот же принцип; секрет для этого приложения — `NOSTROY_PROXY`).

## GitHub Actions
Воркфлоу `.github/workflows/nostroy-leadgen.yml` (в корне репозитория)
запускает это приложение и кладёт `nostroy.xlsx` в репозиторий —
аналогично остальным приложениям. Пока только ручной запуск, до
подтверждения, что источник реально отдаёт данные.
