# Третье приложение — ЕРЗ.РФ + РТС-тендер

Третье, отдельное от корневого сборщика (zakupki.gov.ru + b2b-center.ru)
и от `vacancy-leadgen` (поиск через вакансии hh.ru), приложение. Собирает
лиды из двух новых источников по просьбе — и **выгружает их отдельно
друг от друга**, двумя листами в одном Excel-файле `erz_rts.xlsx`:

- **«ЕРЗ.РФ (застройщики)»** — с сайта erzrf.ru (Единый ресурс
  застройщиков): компании, которые прямо сейчас строят жильё. Застройщик
  на этапе стройки — почти гарантированный потребитель ЖБИ, и это не
  тендер, который ещё нужно выиграть, а прямой контакт с компанией.
- **«РТС-тендер»** — с rts-tender.ru, ещё одной крупной электронной
  торговой площадки (помимо b2b-center.ru из корневого приложения).

## Статус источников

- **ЕРЗ.РФ (`erz.py`)** — откалиброван, работает. Сайт — Angular-
  приложение с server-side рендерингом, реальные данные видны в обычном
  HTML без Playwright. Возвращает топ-рейтинг застройщиков по всей РФ
  (название, ссылка на профиль, доля рынка в регионе, объём стройки в
  м², число проектов, год основания). **Известное ограничение**: у
  сайта нет рабочего текстового фильтра по региону — реальный фильтр
  требует числовой `regionKey`, который нигде не публикуется текстом
  (внутренний ID из БД сайта), поэтому `regions` в `config.yaml` пока не
  используется, и `main.py` делает один запрос без региональной
  привязки. Подробности и как это доделать (посмотреть regionKey в
  браузере) — в докстринге `erz.py`.
- **РТС-тендер (`rts_tender.py`)** — пока не работает. Даже главная
  страница возвращает `Connection reset by peer` — похоже на
  блокировку по IP (как изначально было с zakupki.gov.ru), а не защиту
  по заголовкам/User-Agent. Нужен резидентский прокси (`ERZ_RTS_PROXY`)
  для следующей попытки калибровки — код и воркфлоу уже готовы его
  принять, осталось попробовать с настоящим прокси.

## Установка
```bash
pip install -r requirements.txt
```

## Запуск локально
```bash
python main.py
```
Токен DaData — тот же принцип, что в остальных приложениях: переменная
окружения `DADATA_TOKEN` или поле `dadata_token` в `config.yaml`.

## Накопление между прогонами
Как и в корневом приложении — при каждом прогоне уже выгруженные раньше
лиды (по каждому листу отдельно) не повторяются, добавляются только
новые. Чтобы начать историю заново — удали `erz_rts.xlsx` перед прогоном.

## Настройка — `config.yaml`
- `keywords` — ключевые слова для поиска на РТС-тендер.
- `regions` — пока не используется (см. ограничение ЕРЗ.РФ выше),
  оставлено на будущее.
- `exclude_customer_keywords` — слова в названии, при которых запись
  отбрасывается (казённые/бюджетные организации).
- `pages_per_keyword` — глубина сбора по РТС-тендер.
- `proxy` — на случай блокировки с серверов GitHub Actions (см.
  `ZAKUPKI_PROXY`/`HH_PROXY` в других приложениях — тот же принцип);
  для РТС-тендер сейчас обязателен (см. статус источников выше).

## GitHub Actions
Воркфлоу `.github/workflows/erz-rts-leadgen.yml` (в корне репозитория)
запускает это приложение и кладёт `erz_rts.xlsx` в репозиторий —
аналогично `leadgen.yml`/`vacancy-leadgen.yml`. Пока только ручной
запуск, до подтверждения, что РТС-тендер тоже реально отдаёт данные
(ЕРЗ.РФ уже подтверждён).
