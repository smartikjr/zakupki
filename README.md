# Сборщик лидов ЖБИ — ГК «БЛОК» (MVP)

Ищет новые госзакупки по ЖБИ-номенклатуре, определяет заказчика (ИНН, регион,
руководитель) и складывает всё в Excel. Бесплатный стек.

Работает и локально (на компьютере в России, без прокси), и в облаке через
GitHub Actions по расписанию каждые 6 часов — но для GitHub Actions нужен
**рабочий резидентный** российский прокси (дата-центровый не пропускает
zakupki.gov.ru, см. «Прокси для zakupki.gov.ru»).

## Что делает
1. Тянет закупки по ключевым словам из `config.yaml` со всех включённых источников: ЕИС `zakupki.gov.ru` (44/223-ФЗ) + b2b-center.ru (коммерческие тендеры, см. «Источники»).
2. Убирает дубли по реестровому номеру (независимо от того, под каким законом ЕИС его показала — один и тот же тендер иногда попадает в выдачу дважды).
3. Отсеивает казённые/бюджетные/административные учреждения по названию заказчика — см. «Фильтр по типу заказчика».
4. Обогащает заказчика через **DaData** (бесплатный тариф, 10 000 запросов/день): ИНН, адрес, регион, руководитель, статус, ОКВЭД.
5. Фильтрует по нужным регионам.
6. Помечает тип закупки — «Поставка» (прямая покупка материала) или «Работы» (подряд) — чтобы быстро сортировать по приоритету.
7. Выгружает в `leads.xlsx` (с фильтрами и кликабельными ссылками).

## Честные ограничения
- **Телефона снабженца/ЛПР в открытых данных нет.** На бесплатном тарифе DaData телефонов компании тоже нет (только на «Максимальном», 56 000 ₽/год) — и это всё равно общий номер, а не мобильный закупщика. Инструмент сужает воронку до «горячих» компаний с ИНН и ссылкой; звонок и выход на снабженца — по методичке, вручную.
- **Вёрстка ЕИС иногда меняется.** Если при первом запуске собралось 0 закупок, а в логе видно, что страницы всё же грузились — см. раздел «Если парсер вернул пусто».
- **zakupki.gov.ru не пускает GitHub Actions runners напрямую и через дата-центровые прокси** — нужен именно резидентный/мобильный российский прокси (проверено на практике: дата-центровый прокси падал `503`/`Network unreachable`, резидентный — сработал: 2220 закупок собрано). Подробнее — «Прокси для zakupki.gov.ru».
- По 223-ФЗ ЕИС с 2019 г. не публикует победителей — по нему получаем в основном заказчиков.

## Фильтр по типу заказчика
Разбор реальной выгрузки (664 строки), размеченной руководителем цветом
(красный — не подходит, жёлтый — подходит, зелёный — в точку), показал
две вещи:
1. **Половина строк была дублями** — одна и та же закупка ЕИС попадала в
   выдачу и под 44-ФЗ, и под 223-ФЗ, а дедуп сравнивал `(номер, закон)`,
   а не просто номер. Исправлено — теперь дедуп только по номеру.
2. **Почти без исключений отклонены** заказчики, в названии которых есть
   слово «учреждение» (казённое/бюджетное/автономное — любое: школы,
   больницы, НИИ, вузы), а также «администрация», «департамент»,
   «министерство», «комитет», «таможня», «муниципальное унитарное
   предприятие» — это бюрократия и коммунальные структуры, а не прямые
   покупатели материалов. **Порты в этот список не входят** — они
   остаются.

Оба вывода зашиты в `leadgen.py` (список `DEFAULT_EXCLUDE_KEYWORDS`) и
переопределяются через `config.yaml → exclude_customer_keywords`. На тех
же реальных данных после дедупа и фильтра из 664 «лидов» осталось 124
реальных — и это только по ЕИС, без учёта новых источников ниже.

Дальше это уже вопрос конкретного тендера, а не только формы заказчика
(например, крупная АО-компания может публиковать и «Поставку» товара, и
подрядные «Работы» — вторые обычно менее интересны прямому поставщику
материала). Полностью автоматически это не разрешить — но колонка
«Тип» (Поставка/Работы/Прочее) в выгрузке позволяет быстро отсортировать
и в первую очередь смотреть «Поставка».

## Источники
- **zakupki** (`zakupki.py`) — ЕИС, обязательные для бюджетных/квази-гос.
  закупок 44/223-ФЗ. **Работает**, проверено на живых данных.
- **b2b_center** (`b2b_center.py`) — b2b-center.ru, крупная коммерческая
  тендерная площадка. Частные компании тут размещают тендеры без
  привязки к 44/223-ФЗ — меньше бюрократии, выше доля годных лидов.
  **Работает**, проверено на живых данных (реальный поиск через поле
  `f_keyword`+`searching=1`, результаты — `table.search-results`).
- **fabrikant** (`fabrikant.py`) — fabrikant.ru. **Не работает и сейчас
  выключен** (`config.yaml → sources` его не включает). Это Next.js
  SPA с клиентским поиском: URL-параметры (`query=`) игнорируются,
  сама выдача рендерится только после реального клика по кнопке
  «Найти», а клик не приводит к штатной навигации, которую видит
  Playwright — за 4 раунда отладки (см. git log по `fabrikant.py`) до
  рабочего состояния не дошли. Требует headless-браузер (Playwright,
  уже используется в коде и в `requirements.txt`/workflow) — простой
  requests+BeautifulSoup здесь принципиально не работает. Код оставлен
  в репозитории на случай, если кто-то захочет добить эмуляцию клика
  дальше; включать обратно в `sources` без этого не имеет смысла.

Включённые источники — `config.yaml → sources` (сейчас `[zakupki, b2b_center]`).

## Установка
```bash
pip install -r requirements.txt
```

## Токен DaData (бесплатно)
1. Зарегистрируйся на dadata.ru → включится бесплатный тариф.
2. В личном кабинете возьми **API-ключ**.
3. Положи его в переменную окружения (надёжнее, чем в файл):
   ```bash
   export DADATA_TOKEN="твой_ключ"     # Linux/macOS
   setx DADATA_TOKEN "твой_ключ"       # Windows
   ```
   Либо впиши в `config.yaml` в поле `dadata_token`.

> Без токена скрипт тоже работает — но без ИНН/региона/руководителя (тогда фильтр по регионам лучше очистить: `target_regions: []`).

## Запуск локально и автоматизация
Раз у тебя (как у пользователя из России) есть прямой доступ к
zakupki.gov.ru — прокси не нужен, `zakupki_proxy` в `config.yaml` оставь
пустым. Альтернатива этому разделу — облачное расписание через GitHub
Actions (см. ниже), если настроен рабочий резидентный прокси.

```bash
python leadgen.py
```
Результат — `leads.xlsx` рядом со скриптом.

**Чтобы запускалось само по расписанию** (компьютер должен быть включён
в момент запуска):

*Windows — Планировщик заданий:*
1. `Пуск` → «Планировщик заданий» (Task Scheduler) → «Создать простую задачу».
2. Триггер — например, «Ежедневно» с повтором каждые несколько часов
   (в свойствах задачи можно задать повтор задачи каждые N часов).
3. Действие — «Запустить программу»:
   - Программа: путь до `python.exe` (например `C:\Python312\python.exe`);
   - Аргументы: `leadgen.py`;
   - Рабочая папка: путь до папки с проектом (`...\zakupki`).

*macOS/Linux — cron:*
```bash
crontab -e
# добавить строку (запуск каждые 6 часов):
0 */6 * * * cd /путь/до/zakupki && /usr/bin/python3 leadgen.py >> leadgen.log 2>&1
```

Токен DaData для автозапуска надёжнее прописать в `config.yaml` (поле
`dadata_token`), а не в переменную окружения — планировщик может не
подхватывать окружение пользователя.

## Прокси для zakupki.gov.ru (нужен, только если НЕ в России)
Сайт госзакупок блокирует запросы с зарубежных дата-центровых IP — на GitHub
Actions (и вообще с серверов не в России) запросы к нему либо виснут по
таймауту, либо проксируются, но не проходят дальше.

> **Проверено на практике:** обычный дата-центровый "прокси Россия" не
> помогает — и HTTP-, и SOCKS5-порт падали уже на стороне самого прокси
> (`503 Service Unavailable` / `Network unreachable`), до сайта дело не
> доходило. **Резидентный** прокси — сработал (2220 закупок собрано за один
> прогон). Если один прокси-сервис не пропускает, попробуй другой —
> конкретный провайдер и тип IP решают, а не сам факт наличия прокси.

1. Возьми прокси-сервис с **резидентными/мобильными** российскими IP
   (дата-центровые обычно не работают против антибот-защиты гос. сайтов).
2. Получишь адрес вида `http://логин:пароль@хост:порт` (для SOCKS5 —
   `socks5://логин:пароль@хост:порт`; пакет `pysocks` для этого уже есть
   в `requirements.txt`).
3. Положи его в переменную окружения (в URL обычно логин/пароль — не
   держи в файле):
   ```bash
   export ZAKUPKI_PROXY="http://логин:пароль@хост:порт"
   ```
   Либо впиши в `config.yaml` в поле `zakupki_proxy`.

К запросам DaData прокси не применяется — туда трафик всегда идёт напрямую.

## GitHub Actions — облачный запуск по расписанию
Воркфлоу `.github/workflows/leadgen.yml` запускается каждые 6 часов (cron)
и кладёт свежий `leads.xlsx` прямо в репозиторий, плюс сохраняет как
артефакт запуска.
1. В `Settings → Secrets and variables → Actions` добавь секреты
   `DADATA_TOKEN` и `ZAKUPKI_PROXY` (резидентный, см. раздел выше —
   без него соберётся 0 закупок).
2. Ручной запуск (проверить, не дожидаясь расписания): вкладка
   `Actions → Сбор лидов ЖБИ → Run workflow`.
3. Интервал меняется строкой `cron` в воркфлоу. `0 */6 * * *` = каждые
   6 часов (UTC). Один прогон занимает 10–25 минут в зависимости от
   числа найденных закупок (обогащение через DaData идёт по одной штуке).

## Настройка под себя — `config.yaml`
- `keywords` — что искать (предмет закупки). Уже заполнено под номенклатуру БЛОК.
- `target_regions` — регионы (по адресу заказчика). Пусто `[]` = без фильтра.
- `sources` — список включённых источников: `zakupki`, `b2b_center` (`fabrikant` пока не работает, см. «Источники»).
- `exclude_customer_keywords` — слова в названии заказчика, при которых лид отбрасывается (см. «Фильтр по типу заказчика»).
- `laws` — `[44]`, `[223]` или `[44, 223]` (только для источника `zakupki`).
- `pages_per_keyword` — глубина по каждому ключевику (50 записей на страницу).
- `zakupki_proxy` — прокси для запросов к zakupki.gov.ru (нужен только при запуске не из России, см. «Прокси для zakupki.gov.ru»). При локальном запуске из России оставь пустым.

## Если парсер вернул пусто
Вёрстка сайта могла измениться. Сохрани реальный HTML и сверь селекторы:
```bash
python zakupki.py        # создаст debug_eis.html
python b2b_center.py     # создаст debug_b2b.html
```
Открой файл, найди блок одной закупки и поправь селекторы в
`parse_cards()` соответствующего модуля. В Claude Code это делается за
один заход: дай ему debug-файл и попроси обновить селекторы.

Если нет возможности запустить это локально — тот же дамп можно снять
через GitHub Actions без установки чего-либо на своём компьютере:
вкладка `Actions → Снять HTML для отладки селекторов → Run workflow`
(воркфлоу `.github/workflows/debug-dump.yml`). Он коммитит
`debug_eis.html`/`debug_b2b.html` прямо в репозиторий.
