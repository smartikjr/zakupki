# Сборщик лидов ЖБИ — ГК «БЛОК» (MVP)

Ищет новые госзакупки по ЖБИ-номенклатуре, определяет заказчика (ИНН, регион,
руководитель) и складывает всё в Excel. Бесплатный стек.

**Запускается локально, на компьютере в России** (см. «Запуск локально и
автоматизация» ниже) — zakupki.gov.ru не пускает запросы с серверов GitHub
Actions даже через прокси, поэтому облачное расписание сейчас отключено.

## Что делает
1. Тянет публичную ленту ЕИС (`zakupki.gov.ru`) по ключевым словам из `config.yaml` (44 и 223-ФЗ).
2. Убирает дубли по реестровому номеру.
3. Обогащает заказчика через **DaData** (бесплатный тариф, 10 000 запросов/день): ИНН, адрес, регион, руководитель, статус, ОКВЭД.
4. Фильтрует по нужным регионам.
5. Выгружает в `leads.xlsx` (с фильтрами и кликабельными ссылками на ЕИС).

## Честные ограничения
- **Телефона снабженца/ЛПР в открытых данных нет.** На бесплатном тарифе DaData телефонов компании тоже нет (только на «Максимальном», 56 000 ₽/год) — и это всё равно общий номер, а не мобильный закупщика. Инструмент сужает воронку до «горячих» компаний с ИНН и ссылкой; звонок и выход на снабженца — по методичке, вручную.
- **Вёрстка ЕИС иногда меняется.** Если при первом запуске собралось 0 закупок, а в логе видно, что страницы всё же грузились — см. раздел «Если парсер вернул пусто».
- **zakupki.gov.ru не пускает GitHub Actions runners**, даже через купленный прокси (проверено на практике: и HTTP-, и SOCKS5-порт одного прокси-сервиса упирались в отказ уже на стороне самого прокси — `503`/`Network unreachable`, до сайта дело не доходило). Поэтому облачное расписание сейчас **отключено**, основной сценарий — локальный запуск. Подробнее — «Прокси для zakupki.gov.ru».
- По 223-ФЗ ЕИС с 2019 г. не публикует победителей — по нему получаем в основном заказчиков.

## Установка
```bash
pip install -r requirements.txt
```

## Токен DaData (бесплатно)
1. Зарегистрируйся на dadata.ru → включится бесплатный тариф.
2. В личном кабинете возьми **API-ключ**.
3. Положи его в переменную окружения (надёжнее, чем в файл):
   ```bash
   export DADATA_TOKEN="твой_ключ"     # Linux/macOS
   setx DADATA_TOKEN "твой_ключ"       # Windows
   ```
   Либо впиши в `config.yaml` в поле `dadata_token`.

> Без токена скрипт тоже работает — но без ИНН/региона/руководителя (тогда фильтр по регионам лучше очистить: `target_regions: []`).

## Запуск локально и автоматизация
Основной сценарий. Раз у тебя (как у пользователя из России) есть прямой
доступ к zakupki.gov.ru — прокси не нужен, `zakupki_proxy` в `config.yaml`
оставь пустым.

```bash
python leadgen.py
```
Результат — `leads.xlsx` рядом со скриптом.

**Чтобы запускалось само по расписанию** (компьютер должен быть включён
в момент запуска):

*Windows — Планировщик заданий:*
1. `Пуск` → «Планировщик заданий» (Task Scheduler) → «Создать простую задачу».
2. Триггер — например, «Ежедневно» с повтором каждые несколько часов
   (в свойствах задачи можно задать повтор задачи каждые N часов).
3. Действие — «Запустить программу»:
   - Программа: путь до `python.exe` (например `C:\Python312\python.exe`);
   - Аргументы: `leadgen.py`;
   - Рабочая папка: путь до папки с проектом (`...\zakupki`).

*macOS/Linux — cron:*
```bash
crontab -e
# добавить строку (запуск каждые 6 часов):
0 */6 * * * cd /путь/до/zakupki && /usr/bin/python3 leadgen.py >> leadgen.log 2>&1
```

Токен DaData для автозапуска надёжнее прописать в `config.yaml` (поле
`dadata_token`), а не в переменную окружения — планировщик может не
подхватывать окружение пользователя.

## Прокси для zakupki.gov.ru (нужен, только если НЕ в России)
Сайт госзакупок блокирует запросы с зарубежных дата-центровых IP — на GitHub
Actions (и вообще с серверов не в России) запросы к нему либо виснут по
таймауту, либо проксируются, но не проходят дальше (см. ниже).

> **Проверено на практике:** обычный купленный "прокси Россия" (дата-центровый)
> тоже не помог — и HTTP-, и SOCKS5-порт одного и того же прокси падали уже
> на стороне самого прокси (`503 Service Unavailable` / `Network unreachable`),
> до сайта дело не доходило. Похоже, для обхода блокировки нужен именно
> **резидентный/мобильный** российский прокси, а не дата-центровый — гос.
> сайты часто банят IP-диапазоны хостинг-провайдеров независимо от страны.
> Поэтому расписание в GitHub Actions сейчас отключено (см. ниже), основной
> сценарий — запуск с компьютера в России.

Если всё же хочешь попробовать через зарубежный сервер/CI:
1. Возьми прокси-сервис с **резидентными/мобильными** российскими IP
   (не дата-центровыми — см. предупреждение выше).
2. Получишь адрес вида `http://логин:пароль@хост:порт` (для SOCKS5 —
   `socks5://логин:пароль@хост:порт`; пакет `pysocks` для этого уже есть
   в `requirements.txt`).
3. Положи его в переменную окружения (в URL обычно логин/пароль — не
   держи в файле):
   ```bash
   export ZAKUPKI_PROXY="http://логин:пароль@хост:порт"
   ```
   Либо впиши в `config.yaml` в поле `zakupki_proxy`.

К запросам DaData прокси не применяется — туда трафик всегда идёт напрямую.

## GitHub Actions (опционально, сейчас без расписания)
Воркфлоу `.github/workflows/leadgen.yml` в репозитории остался, но
автоматический запуск по `cron` в нём отключён — zakupki.gov.ru не пускает
GitHub-раннеры (см. выше). Ручной запуск (`workflow_dispatch`) работает,
на случай если появится рабочий резидентный прокси:
1. В `Settings → Secrets and variables → Actions` добавь секреты `DADATA_TOKEN` и (если найдёшь рабочий прокси) `ZAKUPKI_PROXY`.
2. Запуск: вкладка `Actions → Сбор лидов ЖБИ → Run workflow`.

## Настройка под себя — `config.yaml`
- `keywords` — что искать (предмет закупки). Уже заполнено под номенклатуру БЛОК.
- `target_regions` — регионы (по адресу заказчика). Пусто `[]` = без фильтра.
- `laws` — `[44]`, `[223]` или `[44, 223]`.
- `pages_per_keyword` — глубина по каждому ключевику (50 записей на страницу).
- `zakupki_proxy` — прокси для запросов к zakupki.gov.ru (нужен только при запуске не из России, см. «Прокси для zakupki.gov.ru»). При локальном запуске из России оставь пустым.

## Если парсер вернул пусто
Вёрстка ЕИС могла измениться. Сохрани реальный HTML и сверь селекторы:
```bash
python zakupki.py      # создаст debug_eis.html
```
Открой `debug_eis.html`, найди блок одной закупки и поправь селекторы в
`zakupki.py → parse_cards()` (классы `search-registry-entry-block`,
`registry-entry__body-value` и т.д.). В Claude Code это делается за один заход:
дай ему `debug_eis.html` и попроси обновить селекторы.
