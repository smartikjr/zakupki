# Сборщик лидов ЖБИ — ГК «БЛОК» (MVP)

Ищет новые госзакупки по ЖБИ-номенклатуре, определяет заказчика (ИНН, регион,
руководитель) и складывает всё в Excel. Бесплатный стек, запуск по расписанию.

## Что делает
1. Тянет публичную ленту ЕИС (`zakupki.gov.ru`) по ключевым словам из `config.yaml` (44 и 223-ФЗ).
2. Убирает дубли по реестровому номеру.
3. Обогащает заказчика через **DaData** (бесплатный тариф, 10 000 запросов/день): ИНН, адрес, регион, руководитель, статус, ОКВЭД.
4. Фильтрует по нужным регионам.
5. Выгружает в `leads.xlsx` (с фильтрами и кликабельными ссылками на ЕИС).

## Честные ограничения
- **Телефона снабженца/ЛПР в открытых данных нет.** На бесплатном тарифе DaData телефонов компании тоже нет (только на «Максимальном», 56 000 ₽/год) — и это всё равно общий номер, а не мобильный закупщика. Инструмент сужает воронку до «горячих» компаний с ИНН и ссылкой; звонок и выход на снабженца — по методичке, вручную.
- **Вёрстка ЕИС иногда меняется.** Если при первом запуске собралось 0 закупок — см. раздел «Если парсер вернул пусто».
- По 223-ФЗ ЕИС с 2019 г. не публикует победителей — по нему получаем в основном заказчиков.

## Установка
```bash
pip install -r requirements.txt
```

## Токен DaData (бесплатно)
1. Зарегистрируйся на dadata.ru → включится бесплатный тариф.
2. В личном кабинете возьми **API-ключ**.
3. Положи его в переменную окружения (надёжнее, чем в файл):
   ```bash
   export DADATA_TOKEN="твой_ключ"     # Linux/macOS
   setx DADATA_TOKEN "твой_ключ"       # Windows
   ```
   Либо впиши в `config.yaml` в поле `dadata_token`.

> Без токена скрипт тоже работает — но без ИНН/региона/руководителя (тогда фильтр по регионам лучше очистить: `target_regions: []`).

## Запуск локально
```bash
python leadgen.py
```
Результат — `leads.xlsx` рядом со скриптом.

## Бесплатный запуск «постоянно» — GitHub Actions
1. Залей папку в **публичный** репозиторий на GitHub (у публичных — расписание бесплатно и без лимитов).
2. В `Settings → Secrets and variables → Actions` добавь секрет `DADATA_TOKEN`.
3. Готовый воркфлоу уже лежит в `.github/workflows/leadgen.yml` — запускается каждые 6 часов и:
   - кладёт свежий `leads.xlsx` прямо в репозиторий (открываешь с телефона/компа),
   - плюс сохраняет как артефакт запуска.
4. Проверить вручную: вкладка `Actions → Сбор лидов ЖБИ → Run workflow`.

> Интервал меняется строкой `cron` в воркфлоу. `0 */6 * * *` = каждые 6 часов (UTC).

## Настройка под себя — `config.yaml`
- `keywords` — что искать (предмет закупки). Уже заполнено под номенклатуру БЛОК.
- `target_regions` — регионы (по адресу заказчика). Пусто `[]` = без фильтра.
- `laws` — `[44]`, `[223]` или `[44, 223]`.
- `pages_per_keyword` — глубина по каждому ключевику (50 записей на страницу).

## Если парсер вернул пусто
Вёрстка ЕИС могла измениться. Сохрани реальный HTML и сверь селекторы:
```bash
python zakupki.py      # создаст debug_eis.html
```
Открой `debug_eis.html`, найди блок одной закупки и поправь селекторы в
`zakupki.py → parse_cards()` (классы `search-registry-entry-block`,
`registry-entry__body-value` и т.д.). В Claude Code это делается за один заход:
дай ему `debug_eis.html` и попроси обновить селекторы.
